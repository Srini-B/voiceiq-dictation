# Release and CI on Xcode 27 (iOS 27 SDK)

## What and why

App Store Connect accepted 0.7.8 (82) with warning ITMS-90725: the build
used the iOS 26.5 SDK, and from April 2027 iOS uploads must use the iOS 27
SDK (Xcode 27 or later). The release jobs ran on GitHub's `macos-26` image,
whose default Xcode is 26.6 with the iOS 26.5 SDK. Local builds on the Mac
mini already used Xcode 27.

- CI and every macOS job in the release workflow run on the `xcode-27` image
  (GA since 2026-10-15). CI and release still share one image, so a PR
  builds with the Xcode that ships it (see 2026-10-30 in
  `2026-10-29-claude-nemotron-provider.md`).
- `scripts/release-ios.sh` stops before archiving when the selected Xcode's
  iOS SDK is older than 27, and logs the Xcode and SDK versions.
- Deployment targets stay at iOS 17.0 and macOS 14.0.

## Verification

- Mac mini, Xcode 27.0 (iOS 27.0 SDK): `swift test` (187 tests), the macOS
  and iOS Simulator CI builds, and an unsigned Release iOS device build all
  exit 0. The built app's `DTSDKName` is `iphoneos27.0`.
- CI on the `xcode-27-arm64` image: all three jobs pass.
- Xcode 27 raises no deprecation from the 27 SDK. Two macOS warnings were
  fixed: a Combine type used without `import Combine`, and a timer closure
  that captured `self` strongly around a weak inner capture. Older warnings
  are unchanged: three Swift concurrency warnings in VoiceIQCore (also on
  Xcode 26.6), three iOS 17 deprecations in the keyboard, and a doc comment
  in vendored FUTO Swipe.

## Rollback

Revert the commit. Uploads built on `macos-26` keep working until April 2027.
